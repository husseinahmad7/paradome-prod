Architecture you can inspect

Small boundaries, explicit failure states, and evidence beside each decision.

Explore six architecture decisions
Keep the lab inside a modular Django application

A dedicated app owns runs, submissions, outbox events, receipts, and traces. Its transport accepts only lab events, never live posts, chat channels, user IDs, or external URLs. The existing site stays on PythonAnywhere.

Trade-off: this is an in-process demonstration, not an independently deployed service. Every attempt happens during an explicit request; there is no background worker.

Record boundaries · Isolation tests

Commit the message and delivery intent together

The source transaction writes a submission and an outbox event atomically. A failure cannot leave one without the other. A unique idempotency key belongs to the run: replaying the same text returns the original; changing it under the same key returns HTTP 409.

Trade-off: a transactional outbox records intent, not guaranteed delivery. An operator or worker must still make an attempt. Here, you do.

Transaction implementation · Replay and rollback tests

Separate delivery from its acknowledgement

The destination receipt is the observable inbox effect. It commits separately from the source acknowledgement. A unique receipt per event makes retries safe even after the acknowledgement is lost.

Trade-off: this is duplicate prevention inside the controlled adapter, not universal “exactly once” delivery. Real integrations need their own durable idempotency contract.

Sandbox adapter · MySQL concurrency tests

Lease an attempt; reject a stale completion

A short lease and unique claim token identify the current attempt. When a lease expires, the next explicit request can claim the work. A late attempt cannot overwrite a newer result or release its claim. Each event allows at most five attempts.

Trade-off: a lease can expire while work is still running. The unique destination receipt protects the effect; token checks protect source state.

Claim and completion checks · Stale-attempt test

Bind the run to a session, not the shared demo user

The browser’s Django session holds a random owner secret; the run stores only its hash. A run UUID is not enough to open it. Foreign and expired runs return 404. Lab responses are not cached or indexed.

Trade-off: closing a session or logging out can end access before the 24-hour limit. Reset replaces only your run; bounded daily maintenance purges expired records.

Session boundary · Cross-session tests

Ship a compact model with an explicit inference contract

Training happens offline. Production loads versioned JSON and uses Python’s standard library for NFKC normalization, TF-IDF features, linear scores, and softmax. It needs no training framework, GPU, or remote inference service.

Trade-off: a small English classifier has a narrow vocabulary. It can abstain, and unfamiliar English can still be misclassified. Missing or invalid model data does not stop submissions or delivery.
